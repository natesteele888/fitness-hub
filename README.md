# Fitness Hub

Desmond's workout apps — standalone, mobile-first training tools, each a
single self-contained HTML file (no build step, no backend) hosted on
GitHub Pages.

## Apps

| | |
|---|---|
| **Power Program** | 9-week offseason plyometrics, core, and dumbbell program, plus a check-in tab for tracking height, weight, broad jump, plank hold, and 10-yard sprint over time. |
| File | `index.html` |
| Live | [/fitness-hub/](https://natesteele888.github.io/fitness-hub/) |

Every exercise has a tappable "i" next to its name that opens a card with a
focus-area tag, a simple pose diagram, a plain-English how-to, a safety/form
cue, and a "Search a Video Demo" link. That link opens a YouTube *search*
for the move, not a specific hand-picked video — no video URL is hardcoded
anywhere, since there's no way to guarantee a specific link stays live or
keeps showing the right thing.

Progress and check-ins save to `localStorage` on whatever phone/browser opens
the page — no login needed. An optional Sheet sync (below) can mirror them
for a parent; without it, nothing leaves the phone. To change
exercises, reps, phases, or weeks, edit the `WORKOUTS` and `SCHEDULE` data
near the top of the `<script>` block in `index.html`; the check-in metrics
are in the `METRICS` array just above them. The exercise cards are driven by
`EXLIB` (the library entries) and `EX_ALIASES` (mapping every exercise name
used in `WORKOUTS` to a library entry) — add a new exercise to `EX_ALIASES`
and `EXLIB` so its card doesn't come up empty. `POSE_ICONS` holds the shared
diagram set; reuse an existing icon key or add a new one there.

This repo was split out from `desmond-party` (which is just the birthday
RSVP sites) to keep workout apps in their own place as more get added.

## Progress sync (optional)

`apps-script.gs` is a free Google Apps Script backend that copies progress
into a Google Sheet, emails a parent when a day is done, and lets a wiped
phone restore itself. Setup steps are at the top of that file. In short:
run `setup()`, deploy it as a web app, run `showSyncLink()`, then paste the
logged sync link into the app (Program tab > Progress Sync > Save sync link).

The sync link (the `/exec` URL with a random token after a `#`) is the key
to the Sheet. It is made at setup, kept in the script's Script Properties
and on the phone (it rides along in the backup code), and is **never
written into `index.html` or `apps-script.gs`** — this repo is public. Keep
the link and backup codes private. To cut off an old link, delete the
`POWER_SYNC_TOKEN` Script Property, run `setup()` and `showSyncLink()` again,
and paste the new link.

## Daily reminders

`reminders/<start-monday>.ics` holds three events for each of the 63 program
days, 189 in all, each with an alarm:

| | |
|---|---|
| 7:00am | the day's full plan — title, rounds, every move and its reps — plus that day's pump-up line |
| 3:30pm | where he is (day, week, phase, % through) and a prod to tick the session off; names the six measurements on days 1, 22, 43 and 63 |
| 7:45pm | tomorrow's session in the same detail, so he never opens the app cold |

GitHub Pages is static and cannot send a web push, so these ride on the
phone's own calendar instead. There is one file per candidate start Monday
because football runs into the playoffs; the picker on the Program tab points
at the matching file.

Everything is generated by `tools-gen-reminders.js`, which reads `PHASES`,
`WORKOUTS`, the schedule builder and `PUMP` straight out of `index.html`, so
the reminders cannot drift from the program. Change the workouts and re-run
it; never hand-edit the `.ics` files.

**What these cannot do:** report his actual logged progress. The files are
written once, in advance, for all 63 days, and his completions live in
`localStorage` on his phone — nothing on the server knows them. So the 3:30pm
event says where the *calendar* is ("Day 12 of 63") and asks whether he got it
in; it never claims he did. A real "you're 12 of 63 done, 4-day streak" push
needs a server that holds his progress: a Web Push subscription, VAPID keys, a
cron to send on, and the app POSTing its state when it's opened. That is a
backend, not a static file, and it is deliberately not built.
